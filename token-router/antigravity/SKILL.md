# token-router (Antigravity Edition)

토큰은 **매 턴마다 전체 대화 기록을 다시 읽는 비용**에서 가장 많이 소모됩니다.
Antigravity 환경에서는 다음 3가지 핵심 원칙으로 토큰을 극대화하여 절약합니다:
1. **서브에이전트 격리**: 대량 파일 검색, 코드베이스 조사, 데이터 처리는 `flash`/`flash_lite` 서브에이전트로 위임하여 메인 대화창 컨텍스트를 깨끗하게 유지.
2. **스크립트 기반 처리**: 엑셀, CSV, 대형 로그 파일의 원문을 대화창에 출력하지 않고 Python/Node 스크립트로 처리.
3. **세션 분리 (Handoff)**: 긴 대화는 `handoff-MMDD-HHmm.md` 파일로 정리하고 백업 후 새 세션으로 인계.

스크립트 경로: `D:/Antigravity_Skills/token-router/scripts/`

---

## 1. 큰 작업 시작: 계획 수립 및 모델/서브에이전트 라우팅

1. **작업 분석 및 단계 분할**:
   - 현재 모델로 전체 계획을 수립하고, 각 단계를 독립된 단위 작업으로 나눈다.
2. **추천 모델 및 서브에이전트 확인**:
   - `node D:/Antigravity_Skills/token-router/scripts/route.js "<작업 내용>"`를 실행하여 적절한 모델과 서브에이전트 추천을 확인한다.
   - **Gemini Flash Lite**: 단순 검색, 목록 조회, 사소한 텍스트 수정, 번역.
   - **Gemini Flash**: 기능 구현, API 연동, 단위 테스트, 리팩터링, 데이터 처리 스크립트 작성.
   - **Gemini Pro**: 복잡한 시스템 아키텍처 설계, 보안 취약점 분석, 원인 불명의 버그 디버깅 (Thinking Effort: Medium / High).
3. **서브에이전트 적극 활용**:
   - 코드베이스 전체 탐색이나 웹 조사가 필요하면 `invoke_subagent` (TypeName: `research`, Model: `flash` 또는 `flash_lite`)로 위임하여 **핵심 요약만 메인 대화로 수신**한다.

---

## 2. 매 답변 끝: 세션 상태 한 줄 표기

답변의 맨 마지막 줄에 세션 권장 상태를 1줄로 표시한다:

- `세션: 유지 (맥락 안정적)` 또는
- `세션: 새로 시작 권장 → handoff-MMDD-HHmm.md 작성 완료`

### 세션 분리 기준:
- 대화 턴이 20턴 이상 누적되었거나, 수십 개의 도구 호출로 컨텍스트가 비대해진 경우.
- 다음 단계의 작업이 이전까지 논의한 내용과 독립적인 경우.
- 사용자가 "세션 끊어줘", "인수인계 작성해줘"라고 요청한 경우.

## 3. Handoff (인수인계) 및 백업 절차

새 세션을 권장할 때는 망설이지 않고 다음 순서로 즉시 인수인계 준비를 마친다:

1. **프로젝트 스냅샷 백업**:
   - `node D:/Antigravity_Skills/token-router/scripts/snapshot.js`를 실행하여 최근 수정된 파일들을 `<프로젝트>/backup-antigravity/<날짜-시각>/`에 gzip 압축 백업한다.
2. **Handoff 인수인계 파일 작성**:
   - 위치: 프로젝트의 `.handoff/` 디렉터리 (없으면 `D:/Antigravity_handoff/`).
   - 파일명: `node D:/Antigravity_Skills/token-router/scripts/handoff.js name` 결과 사용 (예: `handoff-0927-1240.md`).

### Handoff 파일 양식:
```markdown
# handoff-MMDD-HHmm

## 목표
(전체 작업의 핵심 목표 1~2줄)

## 완료된 작업
- (완료된 단계 및 생성/수정된 핵심 파일 경로)

## 다음 진행 단계
1. (새 세션에서 바로 실행해야 할 작업) — 권장 모델: Flash / Pro
2. (후속 작업)

## 관련 파일 및 스크립트
- `경로` — 파일 역할 및 요약 (대화에 통째로 읽지 말 것)
- `.handoff/` — 이전 작업 일지

## 미완료 / 주의사항
- 스냅샷 백업: `backup-antigravity/`에 보관됨
- 실패한 테스트나 중단된 프로세스 등 새 세션이 즉시 확인해야 할 항목

## 결정 사항
- (확정된 설계 방향, 사용자 요구사항, 라이브러리 제약 등)

## 검증 방법
- (결과 정상 여부를 검증할 명령어: e.g. npm test, curl 등)
```

## 4. 대용량 데이터 (엑셀, CSV, 로그) 처리 원칙

- **대화창에 원문 출력 금지**: 엑셀이나 수천 줄의 CSV/로그 내용을 대화창에 직접 dump하지 않는다.
- **Python / Node 스크립트 활용**: 파싱, 집계, 필터링은 임시 스크립트를 작성하여 터미널에서 실행하고, 결과 요약 수치(JSON/표)만 대화창에 남긴다.
- 스크립트는 `scratch/` 또는 프로젝트 내 스크립트 폴더에 보관하여 재사용 가능하게 한다.

---

## 5. 컨텍스트 비대화 방지 체크리스트

- 명령어 출력이 길어질 것으로 예상되면 파일로 리다이렉트(`> out.log`) 후 필요한 부분만 확인한다.
- 파일 수정 시 전체를 덮어쓰기보다 변경 부분만 정밀하게 수정한다.
- 탐색/조사 작업은 `invoke_subagent`를 사용하여 메인 컨텍스트를 소모하지 않는다.
- 이미 읽은 대형 파일을 반복해서 다시 읽지 않는다.
